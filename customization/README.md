# Lakers MeshCentral customization

> **Important security notice:** MeshCentral is remote-management software. Its agent can provide remote desktop, terminal, file transfer and other device-management capabilities according to server permissions. Deploy it only on systems you own or are explicitly authorized to manage. Tell device owners/admins what is installed, protect the server with TLS and strong authentication, and keep a tested uninstall and backup procedure. Do not use this project for covert access, unauthorized surveillance, credential theft, or security-control evasion.

## Feature map

- **Purple/gold Lakers theme:** `branding/web/public/styles/custom.css`.
- **Wispbyte Node.js launcher:** `wispbyte/start.js`; see `wispbyte/README.md`. It reads the runtime `PORT` and attempts public-host environment detection; if no public hostname is exposed, set `MESH_HOSTNAME`. The launcher assumes proxy isolation when `MESH_TRUSTED_PROXY` is unset, so only use that default if the provider prevents direct access to the origin listener. Hosting compatibility depends on durable storage and network/WebSocket behavior.
- **Windows GUI installer:** `client/LakersAgentInstaller.csproj`; requires UAC and an agent EXE generated by the trusted MeshCentral server. See `client/README.md`.
- **Local wallpaper, diagnostics and crash dump analysis:** `tools/LakersDesktopTools.csproj` builds a GUI for the current user's wallpaper, read-only local reports, and local `cdb.exe !analyze -v` output. These are not remote controls integrated into the MeshCentral web UI.
- **Deployment helpers:** `deploy/`.

No claim is made that a generic free Node.js host supports every MeshCentral feature. Test agent enrollment, WebSocket sessions, file transfer, remote desktop, persistence, and reconnect behavior before relying on a deployment. CI artifacts are unsigned until a release-signing process is configured.
