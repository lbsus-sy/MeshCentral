# Lakers Purple & Gold MeshCentral UI + Client Roadmap

## Implemented in the current draft
- Lakers purple/gold CSS override using MeshCentral's supported custom stylesheet path.
- Docker Compose deployment template with persistent volumes, environment example, backup/update/validation scripts, and safer startup logging.
- Experimental Wispbyte Node.js launcher that reads the assigned runtime port and tries public-host environment variables. If the provider does not expose a public hostname, `MESH_HOSTNAME` remains required. Full compatibility is not guaranteed.
- Windows GUI installer source: no console, UAC elevation manifest, visible consent and confirmation, server-generated agent selection, `-fullinstall` and `-fulluninstall` actions, and local logs.
- Windows desktop tools GUI source: current-user wallpaper selection, local read-only diagnostics, and local crash dump analysis through a user-selected Microsoft `cdb.exe`.
- Root README and customization docs include prominent remote-management consent/security warnings.

## Still required before a production release
1. Run and verify the Windows GitHub Actions build and all validation workflows.
2. Configure protected Authenticode signing for release binaries. Current CI artifacts are unsigned.
3. Test install/uninstall on supported Windows versions and confirm the actual service lifecycle and server reconnect behavior.
4. Test Wispbyte with the actual allocation: persistent storage across restart/redeploy, browser HTTPS, WebSocket upgrades, agent enrollment/reconnect, remote desktop, file transfer, and memory/disk limits. Separate TCP services such as Intel AMT/MPS may not be exposed.
5. Test desktop tools on a disposable Windows machine, including non-admin limitations, wallpaper behavior, and local cdb analysis with a known test dump.
6. If desired, implement a separate consented, permission-scoped remote wallpaper workflow in the MeshCentral web UI. The current wallpaper feature is local desktop tooling, not a remote UI action.
7. If desired, design an authenticated remote diagnostics module with explicit per-device authorization, audit logs, bounded outputs, retention limits, and user consent. The current diagnostics/dump analyzer are local-only.

## Safe installer behavior
- The installer explicitly shows the selected server-specific agent file and asks the operator to confirm authorization.
- UAC is required before installation/uninstallation; normal GUI runtime has no console.
- The agent binary is generated by the user's own MeshCentral server and is not silently downloaded or embedded as a generic reusable payload.
- Logs record file path, hash, action and exit details locally; do not store credentials or reusable enrollment tokens.
- No covert installation, hidden persistence, security-control evasion, or hidden remote access.

## Debugging boundary
The desktop GUI can collect local read-only process/service/event information and run `cdb.exe !analyze -v` against a dump the user selects. Dump files may contain secrets and personal data. Do not upload or share them without review. Do not add remote BSOD, arbitrary process termination, or destructive crash triggers to the production management interface; use disposable isolated test VMs with explicit local confirmation for destructive testing.

## Deployment boundary
MeshCentral's Node.js server needs persistent data and dependable WebSocket/agent connectivity. A Node.js hosting label alone does not guarantee those capabilities. Cloudflare Pages is for static landing pages, not a replacement for the long-running MeshCentral server. A supported VM/container host is the recommended full-featured deployment target.

See `customization/CUSTOMIZATION.md` and `customization/wispbyte/README.md` for the runbooks.
