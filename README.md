# Lakers MeshCentral customization

This repository is a customized fork of [MeshCentral](https://github.com/Ylianst/MeshCentral), the open-source web-based remote device management platform. Upstream license and attribution notices are preserved.

> **Security and consent warning:** MeshCentral is remote-management software. Depending on server permissions, an enrolled agent can enable remote desktop, terminal, file transfer, and other device-management operations. Deploy only on devices you own or are explicitly authorized to administer. Inform device owners/administrators, secure the server with HTTPS and strong authentication, keep backups, and maintain a tested uninstall procedure. Do not use this project for covert access, unauthorized surveillance, credential theft, or security-control evasion.

## Windows EXE builds

GitHub Actions is configured to build two unsigned, self-contained Windows x64 GUI artifacts: `LakersMeshAgentInstaller.exe` and `LakersDesktopTools.exe`. After the **Windows GUI client packaging** workflow completes successfully, open the repository's Actions tab, select that run, and download the artifacts. Check the workflow result; source code or a configured workflow is not proof that an EXE has built successfully. Artifacts expire after 14 days. The executables are unsigned, so Windows may show an unknown-publisher warning.

### One-step agent installation

Download the Windows agent generated by your own trusted MeshCentral server and put `MeshAgent*.exe` beside `LakersMeshAgentInstaller.exe`. Run the installer and approve the standard Windows UAC prompt. After approval, it automatically runs `-fullinstall` without opening an installer window, console, or follow-up dialog. Result and error details are written to `%ProgramData%\LakersMeshCentral\installer.log`. For uninstall instructions, see [the installer guide](customization/client/README.md).

The agent is server-specific; there is no universal agent bundled in the wrapper. The UAC prompt is not bypassed or suppressed. Only approve it when you intend to authorize installation of a persistent remote-management service on a device you own or are authorized to manage.

The desktop tools GUI changes wallpaper for the current signed-in user, collects local read-only diagnostics, and can invoke a locally installed Microsoft `cdb.exe` to analyze a user-selected crash dump. It does not upload reports or dumps.

## Wispbyte compatibility

The launcher reads the provider's assigned runtime port and tries common public-host environment variables. If the host does not expose a public hostname to the process, set `MESH_HOSTNAME` manually. A Node.js runtime alone does not guarantee support for persistent storage, WebSocket upgrades, TLS proxying, or all agent traffic; test these features on your actual allocation before enrolling production devices.

## Status

These are source changes and configured CI builds, not a claim of a completed live Wispbyte deployment. Remote wallpaper is not yet integrated as a first-party MeshCentral UI action; the included desktop EXE changes the current user's local wallpaper. Diagnostics and crash dump analysis are local and user-initiated. No signed release or end-to-end agent session has been certified yet.
